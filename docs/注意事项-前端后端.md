# 比价项目 · 前端/后端交接手册（小白 + AI 辅助版）

> 读者：负责前端和后端的同学。你们不是程序员没关系——这份手册的用法是：
> **看懂名词 → 找到你的任务 → 把"给 AI 的提示词"整段复制给 AI → 按"怎么验收"检查它做对没**。
> 数据侧的完整设计在 `设计文档.md`；这份只管"你要做什么、怎么做、怎么算做对"。

---

## 0. 三分钟看懂整个项目

```
你的电脑上跑一个采集程序
   ↓ 每 30 分钟 / 你点刷新时
它去 ZOL、京东抓价格
   ↓ 写进本地文件
data\price.db      ← 数据库（一个文件，双击打不开，用命令看）
data\snapshot.json ← 给前端的数据快照（一个大 JSON）
   ↓
前端页面读 snapshot.json 画成网页
```

**关键认知**：没有服务器、没有云、不用 npm install、不用数据库软件。所有东西都是**你电脑上的文件**，Node.js 一个程序全包。

## 1. 先看懂这些词（只解释本项目里用到的）

| 词 | 大白话 | 你在哪会遇到 |
|---|---|---|
| **Node.js** | 在电脑上跑 JavaScript 的程序。本机在 `D:\nodejs\node.exe` | 所有命令都以它开头 |
| **`node:sqlite`** | Node 自带的本地数据库，**不用装** | 后端读数据 |
| **SQLite** | 一个文件就是整个数据库，像 Excel 但能用 SQL 查 | `data\price.db` |
| **JSON** | 一种文本格式，长这样 `{"名字":"索泰","价格":529900}` | `snapshot.json`、接口返回 |
| **"分"** | 我们所有价格的单位是**分**。`529900` = ￥5299.00 | 所有 `price` 字段 |
| **ISO 时间** | `2026-10-18T17:38:02+08:00` = 北京时间 17:38:02 | 所有 `captured_at` |
| **快照** | 某一刻抓下来的数据，存成文件后不再变 | `snapshot.json` |
| **口径** | 这个价是"谁、在哪个地区、含不含券"看到的 | `account_kind`、`coupon_scope` |
| **幂等** | 同一商品抓 10 次，库里还是 1 条记录 | 采集器已实现，你不用管 |
| **CDP** | 用程序遥控真实浏览器（抓京东价用） | 只数据侧用，你们不碰 |
| **WAL** | SQLite 的工作模式，让"一边写一边读"不打架 | 已开启，别关 |

## 3. 数据契约（必须按这个理解，不要自己改字段名）

### 3.1 `snapshot.json` 顶层

| 字段 | 含义 |
|---|---|
| `generated_at` | 这份快照什么时候生成的 |
| `counts` | 商品数/报价数/价格点数，用来自检 |
| `products` | 商品清单（一个商品一条） |
| `latest` | 每个商品在每个平台的**最新一条**报价 |
| `history` | 价格历史点，按商品+平台分组 |
| `deal` | 算好的好价判定（前端直接用，**不要自己重算**） |
| `collect_runs` | 最近几轮抓取报告 |

### 3.2 `products` 每条

| 字段 | 含义 | 注意 |
|---|---|---|
| `id` | 商品编号 | 主键 |
| `brand` | 品牌 | **可能为 null**，显示"品牌未知" |
| `model` | 型号全名 | 很长，要截断 |
| `storage` | 容量/显存，如 `12gb` | 可能为 null |
| `image_url` | 网图地址 | 有防盗链，可能 403 |
| `image_local` | 本地图片路径 | **可能为 null**，要回退 |
| `msrp` | 官方指导价（分） | 现在几乎都是 null，别当必有 |
| `match_key` | 去重用的键 | 前端不用管 |

### 3.3 `latest` 每条

| 字段 | 含义 | 注意 |
|---|---|---|
| `price` | 价格（**分**） | 显示时 `/100` |
| `captured_at` | 抓取时间 | **必须显示在页面上** |
| `account_kind` | `anon`/`nonplus`/`plus` | 口径，必须显示 |
| `coupon_scope` | `pre_coupon`=券前价（当前主口径）/ `auto_promo`=已含「限时立减、满减」这类人人可享的自动优惠 / `claim`=含需手动领的公开券 / `none`=未采集。**PLUS、新人、百亿补贴、白条、定向券一律不计**（实测：京东自营显卡 PC 页无公开券区，3/3 抽样为空）|
| `confidence` | `ok` / `partial` | `partial` = 单源或未登录，**不能写"全网最低"** |
| `in_stock` | 1/0/null | **null 表示不知道**，不要显示"有货" |

### 3.4 `history` 每条

```json
{"product_id":3,"platform":"zol",
 "points":[["2026-10-18T17:36:56+08:00",529900],["2026-10-18T17:38:02+08:00",529900]]}
```

- `points` 可能只有 **2 个点**，也可能 20 个，**不要假设 30 个**
- 价格是分；时间是可排序字符串

### 3.5 `deal` 每条

```json
{"product_id":3,"price":529900,"market_min":529900,"msrp":null,
 "discount_vs_msrp":null,"hist_avg":null,"points":2,"platform_count":1,
 "confidence":"partial","is_good_deal":false,"reasons":[]}
```

- `is_good_deal` 直接用，**前端不要自己判断**
- `reasons` 是中文句子，直接显示
- 现在 `false` 且 `reasons` 为空，**这是正常的**（单平台、点数少）

---

### 3.6 单位与字段修正（2026-10-18，必看）

| 项 | 说明 |
|---|---|
| **所有金额单位 = 分** | 包括 `products[].msrp`、`deal[].msrp`、`reference.series[].points[]` 里的 `low_hist/low_day/msrp/jd/tb/pdd/yin`。**没有例外**，显示时统一 `/100` |
| `generated_at` | **数据采集时间**（最新一条报价的时间），不是导出时间 |
| `exported_at` | 本次导出的时间。刷新后 `generated_at` 变了才算真更新 |
| `products[].image_local` | 本地图相对路径（如 `data/images/7.jpg`），不依赖外网；优先用它，回退 `image_url` |
| `products[].active` | 只有 `active=1` 的会出现在快照里（老卡和无报价的已过滤）|
| `deal[].price_flag` | 非 null 表示“价格存疑”（与第三方参考偏离 >40%）。**带这个标记的不能标“全网最低”**，也不能算好价 |
| 刷新验收 | 不要只看 `refreshed:true`，要看 `GET /api/collect/status` 里 `last_refresh.data_changed` |

## 4. 前端的任务（5 步，按顺序做）

> 技术选择已定：**纯 HTML + 原生 JavaScript，单文件，不装任何东西**。原因：不用 npm 就不会现场装包失败。
> 注意：**这不是“离线可用”功能**——数据本身每 30 分钟采集、刷新要联网；这里只是避免网络抖动时白屏。

### F1. 商品列表页

**目标**：把 `products` + `latest` 画成卡片列表。

**怎么验收**：
- 打开页面能看到卡片
- 每张卡有：图、品牌+型号、价格（￥xxxx.xx）、采集时间、口径
- 品牌为 null 显示"品牌未知"，图挂了显示灰块，页面不报错

**给 AI 的提示词（整段复制）**：

```
帮我写一个比价网站的商品列表页。要求：
1. 纯 HTML + 原生 JavaScript，单个 index.html，不要任何框架，不要 npm install，不要 CDN。
2. 数据来自同目录下的 data/snapshot.json（用 fetch 读取）。
3. 渲染 snapshot.products 里的每个商品为一张卡片：
   - brand（可能为 null，显示"品牌未知"）、model、storage（可能为 null）
   - 价格：从 snapshot.latest 里找 product_id 相同的记录取 price。
     price 单位是"分"，显示时必须除以 100 并保留两位小数，前缀 ￥。
   - image_local 优先，没有就用 image_url，都没有就显示灰色占位块（不要显示破图图标）。
   - 卡片底部显示 captured_at 和口径：account_kind、coupon_scope。
4. 如果该商品的 deal.confidence === "partial"，卡片角落加黄色小标签"单源/未含券"。
5. 页面顶部显示 snapshot.generated_at 和 counts。
6. 不要出现"实时""全网最低"字样。
7. 中文注释，说明每段在干什么。
写完后告诉我怎么在本地打开验证。
```

### F2. 价格历史曲线

**怎么验收**：
- 只有 2 个点时能正常画，不报错
- 0 个点时显示"暂无历史，已开始积累"
- 横轴是真实时间，不是等距编号

**给 AI 的提示词**：

```
在商品列表页上增加：点击卡片，弹出该商品的价格历史。
数据来自 snapshot.history 里 product_id 相同的记录，points 是 [[时间,价格分],...]。

要求：
1. 用原生 SVG 画折线图即可，不要引入图表库（不要 CDN、不要 npm）。
2. 价格除以 100 显示为元。
3. 点数处理：0 点显示"暂无历史，已开始积累"；1 点显示一个点；2~3 点画折线+圆点，
   不要画趋势线或拟合曲线（会误导）。
4. 横轴按真实时间等距缩放，纵轴从最低价往下留 5% 边距。
5. 点上鼠标悬停显示"时间 + 价格"。
6. 中文注释。
```

### F3. 到手价的四个档位（最容易被评委追问的地方）

**展示规则（照这个顺序）**：

```
主价    ￥5299.00        ← 页面价，单件、普通用户
副价    领券后 ￥5099.00  ← 有券才显示
提示    再买 ￥101 可用「满 5000 减 300」   ← 门槛没满足的券，只能提示
条件价  凑 3 件 ￥4899 · PLUS ￥5199       ← 单独一行，带条件标签
```

**怎么验收**：
- 门槛没满足的券**没有**被算进主价
- 页面上能看到口径那句话（地区 + 用户类型 + 是否含券）

**给 AI 的提示词**：

```
在商品卡片里展示多档价格，规则如下（业务规则，务必照做）：
1. 主价 = 页面价，永远显示，口径"单件·普通用户"。
2. 副价 = 领券后价，只有当存在"无需满额、可自动叠加"的券时才显示。
3. 提示行 = 存在"门槛未满足"的券时显示，句式："再买 ￥X 可用「满 Y 减 Z」"，
   这个价格绝对不能并进主价。
4. 条件价 = 多件折/会员价/支付立减，单独一行，每项带条件标签，不与主价混排。
5. 卡片底部固定一行小字口径：
   "采集于 {captured_at} · {region 或 '未知地区'} · {account_kind} · {含券/未含券} · 不含支付优惠"
6. 页面不出现"实时价格"，写"更新于 xx:xx"。
7. 中文注释说明每个价格来源对应哪个字段。
```

### F4. 刷新按钮

**流程必须是这样**：

```
点刷新 → POST /api/refresh → 立刻拿到当前数据（可能 refreshed:false 表示被限流）
     → 页面照常显示，右上角"更新中…"
     → 每 2 秒 GET /api/snapshot，比对 generated_at
     → 变了就替换数据，角标消失
```

**怎么验收**：
- 连点 5 次，不报错、不转圈、不白屏
- 60 秒内第二次点，提示"稍后再试"而不是弹错误
- 网络断开时显示上次数据 + “当前离线”提示（降级，不是离线功能）

**给 AI 的提示词**：

```
给页面加"刷新数据"按钮，交互要求：
1. 点击后 POST /api/refresh，立刻渲染返回的 snapshot（不要等抓取完成）。
2. 若 refreshed === false，显示"更新太频繁，{retry_after} 秒后可再试"，不要 alert、不要报错。
3. 若 refreshed === true，右上角显示"更新中…"，然后每 2 秒 GET /api/snapshot，
   比较 generated_at，变了就重渲染并隐藏角标。
4. 最多轮询 3 分钟，超时显示"本次更新未完成，请稍后再试"。
5. 请求失败时保留现有数据，显示"网络不可用，当前显示 {generated_at} 的数据"。
6. 原生 fetch，不引入库。
```

### F5. 模糊搜索 + 候选卡片

**给 AI 的提示词**：

```
加一个搜索框。输入后 GET /api/search?q={用户输入}，返回形如：
{"ok":true,"data":{"candidates":[{"product_id":3,"title":"...","brand":"...","price":529900,
 "image_url":"...","score":85}]}}
要求：
1. candidates 渲染成 5 张横向卡片（图+名称+价格+相似度百分比）。
2. 点某张卡 → POST /api/alias，body {"raw_title":用户输入,"product_id":选中id}，然后跳转详情。
3. 加"都不对"按钮 → POST /api/alias，body {"raw_title":用户输入,"product_id":null}。
4. 没有候选时显示"没找到，换个说法试试（例如只输入型号）"，并给出示例。
5. 原生 JS，中文注释。
```

## 5. 后端的任务（5 步）

> 技术选择：**Node 内置 `node:http` + `node:sqlite`，不装 express**。现场不会挂。

### B1. 起一个只读接口服务

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/snapshot` | 返回当前快照（结构同 snapshot.json） |
| POST | `/api/refresh` | 触发一轮抓取，立刻返回，后台跑 |
| GET | `/api/collect/status` | 是否在抓、上轮报告 |
| GET | `/api/search?q=` | 模糊搜索 Top5 候选 |
| POST | `/api/alias` | 记住用户选的商品 |
| GET | `/api/health` | 健康检查 |

统一外层：`{"ok":true,"data":{...},"error":null,"generated_at":"..."}`
失败：`{"ok":false,"data":null,"error":{"code":"RATE_LIMITED","message":"..."}}`

**怎么验收**：浏览器打开 `http://localhost:8787/api/health` 能看到 JSON。

**给 AI 的提示词**：

```
用 Node.js 内置模块（node:http、node:sqlite）写一个只读 API 服务，不要 express，
不要 npm install。文件 src/serve.mjs，端口 8787。

数据源是本机 SQLite 文件 data/price.db（表结构见同目录 schema.sql，先读它）。
启动时执行 PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000; PRAGMA query_only=ON;

接口：
GET /api/health → {"ok":true,"data":{"db":"ok","last_collect_at":"..."},"error":null}
GET /api/snapshot → 结构与 data/snapshot.json 完全一致（可直接读该文件返回，
  但响应里要有 generated_at 和 counts）
GET /api/collect/status → 最近一轮 collect_run + running 布尔
其余接口先返回 501 占位。

要求：
1. 所有响应头 Content-Type: application/json; charset=utf-8。
2. 时间一律 ISO 8601 带 +08:00。
3. 价格一律输出"分"（整数），不要转元。
4. 中文注释，并告诉我怎么启动、怎么用浏览器验证。
```

### B2. 刷新接口（必须防连点）

规则（照抄，别改）：
- 全站最小间隔 **60 秒**（`last_run_at` 存进数据库，不能只放内存——重启就丢）
- 同一时刻只允许一轮
- 被限流时返回 **200** + `{"refreshed":false,"retry_after":37}`，**不要返回 4xx**

**怎么验收**：连发 3 次请求，第 2、3 次返回 `refreshed:false`。

**给 AI 的提示词**：

```
实现 POST /api/refresh。要求：
1. 从数据库查最后一次抓取时间（用 collect_run 最新一条）。
2. 若距上次 < 60 秒，立刻返回 {"ok":true,"data":{"refreshed":false,"retry_after":剩余秒数}}。
3. 若当前已有一轮在跑（内存变量 + 数据库标记双保险），也返回 refreshed:false。
4. 否则用 child_process.spawn 启动 `node src/collect.mjs --category vga --limit 12`，
   不等待结束，立刻返回 {"refreshed":true,"started_at":"..."}。
5. 采集进程 stdout/stderr 写 logs/collect-{时间}.log。
6. 绝不能在 HTTP 请求里同步跑完抓取（会超时）。中文注释。
```

### B3. 定时抓取（每 30 分钟）

**给 AI 的提示词**：

```
写一个 Windows 计划任务用的脚本 run-collect.ps1：
1. cd 到 D:\dsh work\比价
2. 用 D:\nodejs\node.exe 依次执行 src\collect.mjs --category vga --limit 12 和 src\export.mjs
3. 输出重定向到 logs\collect-{yyyyMMdd-HHmm}.log
4. 出错不要卡窗口（try/catch，错误写日志）
另外给我用 schtasks 注册"每 30 分钟运行一次"的完整命令行。
注意：文件必须存成 UTF-8 with BOM，否则 PowerShell 5.1 会把中文读乱。
```

### B4. 数据体检（演示前必跑）

**给 AI 的提示词**：

```
写 src/check.mjs，做数据体检并打印报告：
1. product 表 brand 为 null 的比例（>30% 警告）
2. price 为 null、或 < 10000 分（100 元）、或 > 10000000 分（10 万元）的记录数
3. price_history 每个 product 的点数分布（min/中位/max）
4. 最近一轮 collect_run 的 ok/fail/anomaly
5. 同一 product 同一 platform 同一时刻是否有重复（应为 0）
输出中文表格 + 最后一行 PASS/FAIL。
```

### B5. 错误码

前端按 `error.code` 显示中文：`NOT_READY`（还没数据）、`RATE_LIMITED`（点太快）、`NOT_AVAILABLE`（源站/脚本不可用）。**不要**把原始报错字符串直接弹给用户。

### F6 / B6. 第三方参考源（B站「显卡日报」）——前端展示，后端只透传

> 位置说明：这一节横跨前后端。**后端只需保证 `/api/snapshot` 原样透传 `reference` 与 `deal[].reference_match`**，展示规则由前端执行。

`snapshot.reference` 里是另一份数据，**不是我们的实测价**：

```json
{"source":"B站 @芝士华莱士 显卡日报（mid 22697887）",
 "note":"第三方整理数据…不参与最低价计算。",
 "dates":["2026-10-12",…,"2026-10-18"],
 "series":[{"model":"RTX 5080",
   "points":[{"date":"2026-10-18","low_hist":7700,"low_day":1489900,"msrp":8299,
              "jd":15699,"tb":14899,"pdd":15599,"yin":15349}]}]}
```

**展示规则（照做）**：

1. 单独一块区域，标题写「第三方参考：B站 @芝士华莱士 显卡日报」，**不要**和我们的价格并排成一张表
2. 每条必须显示日期；顶部显示 `dates` 范围
3. 平台名**用真实名**，从 `reference.platform_names` 取：`jd→京东自营`、`tb→淘宝`、`pdd→拼多多`、`yin→抖音`。其中**抖音是推断**（原文写“某Yin”，他店铺前缀写“某音”），UI 上可以正常写“抖音”，但内部文档和答辩时要能说清这是推断
4. 加一行小字：`数据为第三方整理，非本站实测；仅供参考，不参与最低价计算`
5. `low_hist` = 该型号历史最低，`low_day` = 当日最低，`msrp` = 官方原价（可当指导价展示）
6. **允许**用它画趋势（例：RTX 5080 七天内 12374 → 14899，+20%）；**不允许**把它写进 `deal.market_min`

**每个商品还多了一个 `reference_match` 字段**（可能为 null）：

```json
"reference_match": {"ref_model":"RTX 5080","ref_days":7,"ref_low_day_latest":14899,
  "ref_jd_latest":15699,"ref_msrp":8299,"ref_change_pct":20.4,
  "note":"系列级参考（第三方整理），不等于本商品的实测价"}
```

含义：这个具体商品对应他表里的哪个**系列**、该系列近 N 天涨跌多少。可以直接做“这张卡近 7 天涨了 20.4%”这类提示。**注意 `ref_change_pct` 是系列级的，不是这个商品的精确涨幅**，UI 上要写“参考系列”。

**给 AI 的提示词**：

```
snapshot.deal[i].reference_match 里是"该商品对应的第三方参考系列"，可能是 null。
请在每个商品卡上：如果 reference_match 非 null，显示一行小字
"参考系列 {ref_model} · 近 {ref_days} 天 {ref_change_pct}%（系列级）"，
涨幅为正显示红色向上箭头，为负显示绿色向下箭头，为 0 显示灰色横线。
null 就不显示这一行。中文注释。
```
**给 AI 的提示词（独立参考区块）**：

```
数据里有一个 snapshot.reference 字段，是第三方参考源（B站某UP主的显卡日报转录）。
请做一个独立的"第三方参考"区块：
1. 与主列表视觉分隔（不同背景色、加"第三方参考"标签）。
2. 按型号展示 dates 范围内 low_day 的折线（原生 SVG，不引入库）。
3. 每个型号显示最新一天的 jd/tb/pdd/yin 四个价格，平台名从 reference.platform_names 取。
4. 每条数据旁边显示日期；顶部显示数据覆盖的日期范围。
5. 区块底部固定一行小字："数据为第三方整理，非本站实测；仅供参考，不参与最低价计算"。
6. 不要把这部分价格和我们的 deal.market_min 混在一起计算或排序。
```

## 7. 常见错误 → 怎么解决

| 现象 | 原因 | 解决 |
|---|---|---|
| `curl` 报 `schannel ... SEC_E_NO_CREDENTIALS` | 本机 curl 的 TLS 后端坏了 | **别用 curl**，一律 `node` + `fetch` |
| ZOL 中文全是乱码 | 页面是 GBK | 必须 `new TextDecoder("gbk")` |
| `database is locked` | 采集器正在写 | 等它跑完；确认开了 WAL |
| 端口 8787 被占 | 上次服务没关 | `Get-NetTCPConnection -LocalPort 8787` 查 PID 后 stop |
| 图片显示不出来 | 防盗链 | 用 `image_local`，没有就灰块，别显示破图 |
| 价格显示成 52.99 | 除 100 除了两次 | 只在渲染时 `/100` 一次 |
| 时间显示成 `...T09:38:02.000Z` | 时区没处理 | 统一输出 +08:00 |
| `npm install` 卡住 | 本项目**不需要任何依赖** | 放弃 npm，用 Node 内置模块 |
| 页面空白 | `fetch` 被 CORS 拦 | 用 `node src/serve.mjs` 起服务，访问 http://localhost:8787 |
