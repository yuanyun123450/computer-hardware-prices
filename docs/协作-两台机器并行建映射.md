# 协作：两台机器并行建立「商品 ↔ 京东 SKU」映射

> 结论先说：**可以并行**。京东的限流是按 **IP / 会话**的，两台机器各自独立——
> 前提是**同一份商品清单**（否则 product_id 对不上），并且用分片避免重复劳动。

---

## 一、原理与边界

| 项 | 说明 |
|---|---|
| 为什么能并行 | 京东频控按 IP，两台机器互不影响 |
| 为什么必须同源 | 映射用 `product_id` 对齐；商品清单不同会导致错配（合并脚本会逐条校验型号）|
| 需要登录吗 | 需要。京东搜索未登录会跳登录页，B 机器要在自己的浏览器里扫一次码 |
| 券/个人信息 | **不涉及**。映射只记录"我们的商品 → 京东 SKU"，不存任何账号券 |

---

## 二、B 机器（另一台电脑）要做的

1. 解压 **`交付-后端-v2.zip`**（里面有 `jd_match.mjs` / `jd_export.mjs` / `cdp.mjs`）
2. 起一个带调试端口的浏览器并登录京东：
   ```powershell
   # 用技能脚本起浏览器（或直接用 Edge 加 --remote-debugging-port=9222）
   node .dsh\skills\browser-cdp\scripts\browser.mjs start --profile "D:\pwatch-profile" --url "https://www.jd.com/"
   # 扫码登录后确认能进 home.jd.com
   ```
3. 跑分片（**第 1 片，共 2 片**），间隔保持随机：
   ```powershell
   node src\jd_match.mjs --shard 1/2 --limit 6 --gap-min 90000 --gap-max 180000
   ```
   → 处理 `product_id % 2 === 1` 的商品
4. 导出结果并回传：
   ```powershell
   node src\jd_export.mjs --out data\share\jd-from-B.json
   ```
   把 `data\share\jd-from-B.json` 发回来。

> 若中途撞到"PC频控页"，脚本会**自动熔断 60 分钟**（写 `data/.jd-cooldown.json`），
> 到点再跑同一命令即可，已做的不会丢。

## 三、A 机器（我这边）要做的

```powershell
# 1) 跑第 0 片
node src/jd_match.mjs --shard 0/2 --limit 6 --gap-min 90000 --gap-max 180000

# 2) 合并 B 的产出
node src/jd_merge.mjs data/share/jd-from-B.json --dry   # 先看会改多少

# 3) 确认绑定情况
node -e "const{DatabaseSync}=require('node:sqlite');const d=new DatabaseSync('data/price.db');console.log(d.prepare('SELECT status,COUNT(*) n FROM jd_match GROUP BY status').all())"
```

## 四、合并的安全规则（`jd_merge.mjs` 已实现）

| 规则 | 行为 |
|---|---|
| 文件类型不对 | 直接拒绝（只认 `kind:"jd-match-export"`）|
| 商品总数不同 | 打印警告，但仍逐条校验 |
| `product_id` 不存在 | 跳过 |
| **型号不一致** | **跳过并列入冲突**（防 id 漂移错配）|
| 两边都 matched 但 SKU 不同 | **不覆盖**，列入冲突，人工裁决 |
| 本地已 matched 且 SKU 相同 | 跳过（幂等）|
| 其他 | 写入；`status=matched` 的同步 `product.jd_sku` |

冲突会打印明细，格式：

```json
{"product_id":8,"local":"索泰RTX4070...","remote":"华硕RTX4070..."}
```

## 五、效率参考

| 台数 | 每批 | 随机间隔 | 每小时 | 剩余 113 个所需 |
|---|---|---|---|---|
| 1 台 | 6 | 90~180s | 9~12 | 约 10~12 小时 |
| **2 台** | 6 | 90~180s | **18~24** | 约 5~6 小时 |
| 2 台（白天加速） | 10 | 60~120s | 30~40 | 约 3 小时 |

## 六、注意事项

1. **不要共用同一个京东账号高频抓取**——虽然限流看 IP，但账号行为也会被记录
2. 两台机器各自有独立的熔断状态（`data/.jd-cooldown.json`），互不影响
3. 合并是**只增不减**：不会删你已有的映射，只补空缺/更新 review
4. 合并后记得跑一次 `node src/export.mjs`（导出快照），前端才能看到新的京东价
