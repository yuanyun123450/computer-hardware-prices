## 二、页面要分六块（按优先级）

### 1. 商品列表（P0）
- 数据：`products[]` + `latest[]`（按 `product_id` 关联）
- 每张卡：本地图、品牌+型号、价格 `￥xx.xx`、采集时间、口径
- `deal[].price_flag` 非空 → 显示“价格存疑”，**不许**再标“最低”
- `confidence === "partial"` → 显示“单源/未含券”

### 2. 到手价四档（P0）
```
主价   ￥5299.00        券前价（当前所有数据都是券前）
副价   领券后 ￥5099.00   ← 暂时没有数据源，先隐藏这行
提示   再买 ￥101 可用「满5000减300」  ← 暂时隐藏
条件价 凑3件/PLUS/白条   ← 暂时隐藏
```
**必须写一行口径**：`券前价 · 单件 · 普通用户 · 不含券/不含支付优惠`

### 3. 价格历史曲线（P1）
- 数据：`history[]`，`points: [[时间, 价格分], ...]`
- 点数 4~6 个（不要假设 30 个）；0 点显示“暂无历史”；别画趋势拟合线

### 4. 刷新（P1）
- `POST /api/refresh` → 立刻渲染当前快照，角标“更新中…”
- 每 2 秒 `GET /api/collect/status`，看 `last_refresh.data_changed`
- **`data_changed === false` 要提示“本次未抓到新数据”**，不要假装成功
- `data_changed === true` 再 `GET /api/snapshot` 换上新的

### 5. 模糊搜索 + 候选选择（P1，你的重点）
用户输 “索泰4070s 天启”（可能不完整/有错），流程：
```
输入 → GET /api/search?q=xxx
     → 返回 candidates: [{product_id, title, brand, price, image_url, score, why}]
     → 渲染 5 张候选卡（图+名+价+相似度%+匹配理由）
     → 点一张 → POST /api/alias {raw_title, product_id} → 跳详情
     → 点“都不对” → POST /api/alias {raw_title, product_id: null} → 提示已记录
```
- 候选为空时给示例：“试试只输型号，如 4070 SUPER”
- **不要**在前端自己做模糊匹配（词典和规则在数据侧，两边算会不一致）

### 6. 第三方参考（P2）
- 数据：`reference.series[]`，`platform_names` 已给真实平台名
- 单独一块、不同底色、标“非本站实测”，**不与主表混排**
- 可以做“这张卡对应系列近 7 天涨了 20.4%”（`deal[].reference_match`）

## 七、券后价（P0，项目主打卖点）

数据侧已经定死口径：**主数据是券前价；券后价单独一条链路，只用用户自己的券。**

### 7.1 三档价展示（照这个顺序）

```
页面价        ￥3388.37       ← 主数据，所有人一样
平台自动立减   -￥10.00        ← 人人可享（coupon_scope = auto_promo）
你的券        -￥300.00       ← 只有检测/填到才有；标注"需登录京东"
─────────────────────────
你的到手价    ￥3078.37
提示          再买 ￥1611.63 可用「满5000减300」
```

硬规则：

1. **券后价不能和主数据混排**，也不能参与“全网最低”
2. 每一档都要有来源标签：`平台价` / `自动优惠` / `用户券`
3. 底部固定一行：`个人券与会员价因人而异，仅供你本人参考`
4. 券门槛没满足 → 只进提示行，**不许**并入到手价

### 7.2 「我的券」两种来源

| 来源 | UI | 说明 |
|---|---|---|
| **扩展自动检测**（P0） | 按钮「检测我的京东券」→ 引导安装扩展 → 装好后一键同步 | 需要用户在京东页登录；扩展只读 DOM，不读 cookie |
| **手动填写**（P1 兜底） | 门槛/面额两个输入框 + 「算算」 | 扩展没装也能演示 |

### 7.3 取数流程

```js
// 1) 拿券（扩展上报的，可能为空）
const r = await fetch(`/api/user-coupons?sku=${sku}`);
const { coupons } = (await r.json()).data;

// 2) 让后端算（不要在前端算券）
const q = await fetch("/api/quote", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ price, auto_promo, user_coupons: coupons }),
});
const { data } = await q.json();
// data = { price, price_promo, price_user, final, applied, notes }
```

**不要在前端自己算券叠加规则**（互斥/可叠加/取最优），那是后端 `/api/quote` 的职责，两边算必不一致。

### 7.4 没有券 / 没装扩展时的降级

- 没券：只显示 `页面价` 和 `平台自动立减`，下面一行小字“未检测到你的券（需登录京东+安装扩展）”
- 没装扩展：给一个“安装扩展”的说明弹层，**不要**跳转外链下载
- 扩展装了但没登录：提示“请先在京东登录，再回到本页点同步”

### 7.5 验收

- [ ] 无券时到手价 = 页面价 − 自动立减，且不发任何券请求报错
- [ ] 有券时显示三档 + 到手价，能对上后端返回的 `final`
- [ ] 门槛没满足的券只出现在 `notes`，不进到手价
- [ ] 页面任何地方都看不到“已保存你的券”（我们确实不存）
- [ ] 手动填券和扩展同步，两条路算出来的结果一致

## 十、【产品方向变更·2026-10-19】导航页：主价 = 京东实时价

### 10.1 页面结构（按负责人要求）

```
┌─────────────────────────────────────────────┐
│ 商品名（来自 ZOL 的型号/图片/品类，做导航）   │
│                                             │
│   ￥3388.37        ← 主价：京东实时价（大字） │
│   京东自营 · 更新于 21:30                    │
│                                             │
│   参考价 ￥3399（ZOL，第三方汇总，可能滞后）  ← 小字、灰色
└─────────────────────────────────────────────┘
```

**三条硬规则**：

1. **主价只能是京东实时价**（`deal[].price_live`）；没有就显示 **「无价格信息」**（不是“暂无实时价”、更不许用 ZOL 价顶替）
2. **ZOL 价放小字**（`deal[].price_reference`），并注明「第三方汇总，可能滞后」
3. 用 `deal[].price_role` 判断：`live` = 有实时价；`reference_only` = 只有参考价（主价位显示「无价格信息」）

### 10.2 数据字段（本轮新增）

| 字段 | 含义 |
|---|---|
| `deal[].price_live` | 京东自营实时价（分），可能为 `null` |
| `deal[].price_reference` | ZOL 参考价（分），可能为 `null` |
| `deal[].price_role` | `live` / `reference_only` / `null` |

> `deal[].price` 仍然保留（历史字段），但**导航页主价请用 `price_live`**，不要再拿 `price` 当主价。

### 10.3 当前覆盖（诚实告知）

| 有京东实时价的商品 | **5**（会随定时任务增加）|

所以导航页会出现大量「暂无实时价」的卡片——**这是当前真实情况，不要用假数据填满**。

### 10.4 验收

## 十一、【新增 P1】「京东对应商品」确认界面

### 11.1 背景

数据侧在批量建立「我们的商品 ↔ 京东 SKU」映射：能自动确认的会直接绑定，**不确定的进 `review` 待人工点选**。
你的界面要让人（或你自己）能快速确认这些待定项。

### 11.2 接口

```
GET  /api/jd-match?status=review&limit=50
POST /api/jd-match   {"product_id":8,"jd_sku":"100012345678"}
```

### 11.3 界面要求

- 独立入口（比如顶部「京东对应关系」按钮），显示三个计数：`matched / review / none`
- 每个 review 项：左边我们的商品（图+型号+当前参考价），右边 3 个京东候选（标题+价格+是否自营）
- 点某个候选 → `POST /api/jd-match` → 该商品从 review 列表消失，`matched` +1
- 提供「先跳过」按钮（本地隐藏，不写库）
- 空态：`暂无待确认商品`
- **不要**自己判断候选对不对——只展示、只提交用户的选择

### 11.4 验收

- [ ] 打开列表能看到 `counts`
- [ ] 点候选后该条消失、计数变化
- [ ] 确认过的商品，导航页主价会变成京东价（刷新后）
