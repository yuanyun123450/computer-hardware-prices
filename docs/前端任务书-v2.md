## 3. 页面结构

```
┌ 顶部说明条 ─────────────────────────────────────────────┐
│ 主价 = 京东自营实时抓取价；参考价 = ZOL 第三方汇总，可能滞后  │
└────────────────────────────────────────────────────────┘
品类导航：全部80 · 显卡14 · 内存10 · 电源12 · 机箱12 · 键盘12 · 投影8 · 路由6 · 笔记本6
（名字取 snapshot.category_names，空品类不显示）

┌ 商品卡 ──────────────────────────────┐
│ [本地图]  品牌 型号 12GB               │
│                                       │
│    ￥3388.37        ← 主价（大字）      │
│    京东自营 · 更新于 21:52              │
│                                       │
│    参考价 ￥3399（ZOL，可能滞后）        │ ← 小字、灰色
│    [价格存疑] [单源/未含券]             │
└───────────────────────────────────────┘

京东无对应商品的卡：
┌ 商品卡 ──────────────────────────────┐
│   无价格信息           ← 主价槽位      │
│   参考价 ￥1299（ZOL，可能滞后）        │
└───────────────────────────────────────┘
```

**三条硬规则**：

1. 主价只用 `deal[].price_live`；为 `null` → 显示 **「无价格信息」**，**禁止**用 ZOL 价顶替
2. ZOL 价用 `deal[].price_reference`，小字 + 注明「第三方汇总，可能滞后」
3. `deal[].price_flag` 非空 → 打「价格存疑」标签，且不参与任何排名

---

## 4. 字段表（本轮新增，务必按这个取）

| 字段 | 含义 | 注意 |
|---|---|---|
| `deal[].price_live` | 京东自营实时价（分） | `null` = 无对应京东商品 |
| `deal[].price_reference` | ZOL 参考价（分） | 可能滞后，做小字 |
| `deal[].price_role` | `live` / `reference_only` / `null` | 决定主价位显示 |
| `deal[].price_flag` | 价格存疑 | 非空 → 打标 + 不排名 |
| `deal[].confidence` | `ok` / `partial` | `partial` 不许说"最低" |
| `products[].image_local` | 本地图相对路径 | 断网也在 |
| `snapshot.category_names` | 品类中文名 | 别写死中文 |
| `snapshot.reference` | 第三方参考 | 独立区块，标"非本站实测" |

> 金额一律「分」，显示时 `/100`，没有例外。

## 5. 接口

| 方法 | 路径 | 用途 | 说明 |
|---|---|---|---|
| GET | `/api/snapshot` | 全量数据 | `{ok,data}`，`data` = snapshot.json |
| **GET** | **`/api/jd-price?product_id=`** | **单商品京东实时价** | **按需抓取，5 分钟缓存** |
| GET | `/api/jd-match?status=review` | 待确认的京东对应关系 | 含 Top3 候选 |
| POST | `/api/jd-match` | 确认映射 | `{product_id, jd_sku}` |
| POST | `/api/refresh` | 触发 ZOL 采集 | **只采 ZOL，不刷京东价** |
| GET | `/api/collect/status` | 刷新进度 | 看 `last_refresh.exits` |
| GET/POST | `/api/user-coupons` | 用户券 | 内存，TTL 10 分钟 |
| POST | `/api/quote` | 券后价计算 | 前端不许自己算 |

**`/api/jd-price` 返回三种情况（都要处理）**：

```json
{"available":true,  "price":288837,"captured_at":"…","cached":false}   // 抓到了
{"available":false, "reason":"no_sku"}                                 // 没关联京东商品
{"available":false, "reason":"fetch_failed","last_price":288837,"last_captured_at":"…"}  // 本次没抓到，有上次价
```

规则：`fetch_failed` 时**显示「无价格信息」+ 上次价格小字**，不要显示成实时价。

## 6. 任务清单

### F1（P0）导航页骨架
品类导航（前端过滤）+ 卡片网格 + 顶部说明条。
**验收**：切品类数字对；空品类不出现；顶部说明条文案正确。

### F2（P0）主价槽位规则
按 `price_role` 渲染：`live` → 京东价 + 更新时间；`reference_only` → 「无价格信息」+ ZOL 小字。
**验收**：随便找 3 张卡（1 有京东价、1 只有参考价、1 存疑），显示都符合规则。

### F3（P0）按需实时价
- 卡片「更新价格」按钮 → `GET /api/jd-price?product_id=x` → 更新主价与时间
- 或用户展开详情时自动请求（**每张卡 5 分钟内只请求一次**）
- 三种返回都要处理（见第 5 节）
**验收**：点更新后主价变化或提示"本次未抓到，显示上次价格"；不出现假实时。

### F4（P1）券后价
用户券（扩展上报/手填）→ `/api/quote` → 显示到手价；无券时只显示主价 + 立减。
**验收**：无券不报错；有券时到手价 = 后端返回的 `final`。

### F5（P1）京东对应关系确认
`/api/jd-match?status=review` 列表 + 点选确认。
**验收**：确认后该商品从 review 消失、计数变化；刷新导航页能看到京东价。

### F6（P1）价格历史
`history[]` 里 `platform` 分开画（京东 / ZOL 不同色），标清来源；点数少也要能画。
**验收**：0/1/2 个点都不报错。

### F7（P0）刷新语义
`/api/refresh` 只采 ZOL。按钮文案写清「更新参考价（ZOL）」；
京东价走 F3 的单品实时接口，两者**不要混在一个按钮里**。

### F8（P1）验收脚本 + 演示脚本
- `tests/accept-front.mjs`：至少 8 条断言（结构、121→124 商品、分单位、price_role、图片 200、无假"最低"）
- `演示脚本.md`：3 分钟流程（导航 → 京东价 → 实时更新 → 券后价 → 参考价）
